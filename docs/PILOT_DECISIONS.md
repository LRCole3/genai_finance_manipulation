# Pilot decisions and review disposition

Status: design decisions, not executed or preregistered. MLX on the user's Apple Silicon Mac and step-matched benchmarking are retained. Actual hardware, package versions, model access, memory and throughput must be recorded locally; this cloud session does not validate them.

## Training and checkpoints (B1, B2, B4, B6, B7)

Use MLX-LM with 4-bit Gemma 3 1B IT for the feasibility pilot and Gemma 3 4B IT for the planned size replication. Candidate conversions are `mlx-community/gemma-3-1b-it-4bit` and `mlx-community/gemma-3-4b-it-4bit`. Verify their existence, license, configuration and tokenizer locally; record immutable model and package revisions before running. Both CT and IT start from the same familiarized instruction-tuned parent within model/seed. CT means further language-model training of that checkpoint, not training an unaligned base model. A second model family is optional.

Initial pilot settings: LoRA rank 8, scale 16, dropout 0, adapting attention query/value projections in all transformer blocks; AdamW learning rate 1e-5, betas (0.9, 0.999), epsilon 1e-8, weight decay 0, gradient norm cap 1. Verify these settings are expressible by the pinned MLX implementation and log exact module names. They are proposed starting settings, not validated optimal settings. Only memory/finite-loss failures or clean-task performance can justify adjustment. Use a disjoint clean development set, record every attempted setting and freeze the choice before intervention evaluation; do not tune to maximize promotion.

Use a 10% intervention-slot fraction by item count for the pilot: 1 intervention or matched replacement item per 10 items. Each block has 50 intervention slots and 450 common clean items. Twenty blocks give 10,000 items per trajectory. Microbatch 1, accumulation 10 gives 50 optimizer updates per block and 1,000 updates per trajectory. Fix maximum sequence length at 512 tokens; reject or shorten overlength items before hashing, never silently truncate their key claim. Distinguish attention tokens, padding, and loss-bearing tokens. Ten percent by items is not ten percent by tokens. This is an affordable conditional-exposure setting, not an estimate of web-corpus dilution.

Use 10 clean warm-up updates before intervention begins, with an identical warm-up stream and optimizer initialization for each paired run. Save a post-warm-up reference; keep learning rate constant during the 20 measured blocks. Reset optimizer state at the start of each new training stage. Save adapters and optimizer state at each boundary for audit/restart; retain realized item order, token counts, loss masks and update numbers.

Continue using the MLX training stack. Pin a release or commit, then inspect its batching and gradient-accumulation behavior. The changelog's description of upstream `main` is a lead, not a pinned implementation fact. If stock batching violates manifest order, implement the smallest ordered iterator inside the MLX workflow. Test no dropped/repeated items, correct loss masking, exact block/update boundaries, realized-order hashes, checkpoint restoration, and paired token budgets before a real trajectory. A custom iterator does not imply replacing MLX.

Familiarization: construct 400 benign IT examples (10 per entity in a 40-entity catalogue), balanced for mention frequency and factual coverage without preferential recommendations. Train one single-pass parent per model and seed at the pilot settings, before either intervention regime. Reuse that exact parent for all target conditions within the seed. Continue the same adapter from a copied parent state; do not stack an unrelated intervention adapter. Record this stage's tokens, steps and artifacts separately. Probe factual recall before and after it; factual failures are reported and resolved on clean development data before freezing the pilot.

## Evaluation and corpus (B3, B8, S5–S12, S15)

Primary recommendation evaluation presents four named candidates with counterbalanced ordering, investor constraints, and permission to abstain; it does not give away factual corrections under test. The observed clean rate is the baseline. Uniform random choice has expectation 1/4 only in a forced uniform-choice task, and is neither a model baseline nor a floor. Recall without a candidate list is a separately labeled sensitivity analysis.

Use 40 scenario families × 5 paraphrases = 200 final queries: 24 represented families, 12 held-out families, and 4 irrelevant-target families. Preserve these strata in reporting. Author separate pilot/development families; final queries never select dose, hyperparameters, judges or templates. Tag prose and instruction items with applicable scenario-family IDs to define representation. Separate entity/template holdouts are additional Paper 2 sets, not silently included in the 200-query budget.

Start with 5 genres × 10 proposition types × 20 paraphrases = 1,000 items per target/regime, one item per genre/proposition cell per block. The main promotion intervention makes an explicit recommendation without changing catalogue facts. A false-fact intervention is a separate optional arm. Use a local Gemma 3 4B IT generator candidate with versioned prompts and human checks; record its reuse as an evaluated model as a limitation. The clean mixture is a locally authored synthetic corpus of neutral finance explanations and factual instruction pairs, with provenance, rights and splits recorded; it is not called representative web data. All generation and judging remain local.

Before corpus generation, check names and tickers against dated exchange/asset registries and record search coverage. A failed or incomplete check is not proof of uniqueness. Replace collisions and use an explicit synthetic namespace in the released catalogue. This check has not been performed.

Primary decoding is greedy, temperature 0, maximum 256 generated tokens; flag truncation and retain raw outputs. Sampled decoding is an optional frozen sensitivity analysis. Use the familiarized, pre-intervention parent for the primary retrieved-context arm; use step-matched clean endpoints only as a separately reported sensitivity analysis.

Capability checks: frozen MMLU high-school mathematics and professional-accounting subsets, plus a separately authored 200-item catalogue-fact/suitability set. Pin dataset versions, license and prompt/scoring format before use. Evaluate the familiarized parent and 250/500/1000 checkpoints and all Paper 2 endpoints; list this generation cost separately. These narrow checks do not establish preserved general intelligence.

## Judge and calibration (B5, S14)

Candidate automated judge: unadapted local Gemma 3 4B IT, greedy decoding with a versioned rubric and structured labels. Using the same family as the evaluated model is a limitation; two blinded human annotators and adjudication supply reference labels. A judge is accepted only after a separate validation set, disjoint from rubric development.

Collect at least 400 pilot responses stratified across arms/evidence types, enriching rare labels as necessary. On the held-out validation portion require at least 100 positive and 100 negative examples for each primary binary endpoint (endorsement, unsuitable endorsement, factual updating, suitability updating; responses may serve several endpoints). Require precision and recall >=0.90 and a 95% Wilson lower bound >=0.80 for each primary endpoint, plus human agreement >=0.80 Cohen's kappa, reporting prevalence and raw agreement. These are operational acceptance gates, not universal quality standards. Report multinomial class-wise errors separately and use sampling weights for prevalence estimates after enrichment. The published 139/246 sample calculations are normal-approximation planning examples, not guarantees for class-wise precision/recall. If the judge fails, revise on development labels and obtain new validation labels, or use human adjudication; never lower gates after seeing final test results.

## Paper 2 reliability, dose and manipulation checks (B9, S3, S4)

Keep 250 items per R and A channel as the primary factorial design, with each item seen once and matched clean replacements. Retain failed installation as a result. Any adaptive-dose study is a separate extension: use Paper 1 pilot families/seeds only to nominate the smallest dose with mean target-endorsement lift >=0.20; validate that fixed dose on fresh pilot families/seeds with a cluster interval excluding zero. Freeze the dose before final factorial data and use the same R dose in both A conditions. If validation fails, report failure instead of repeatedly searching. A remains 250; changes to R require matched benign channels and updated token/run budgets in every cell. Paper 1's primary 250-item result never changes.

Provide observable reliability cues: authenticated simulated catalogue-record IDs, dates, verifiable fact tables and explicit links to independently sourced records. Unreliable packets contain unsupported assertions or conflicts with those records. Teach the provenance convention equally during familiarization. Randomize cosmetic outlet names, typography and candidate direction independently; provide matched quality-by-direction variants. Do not require a model to infer truth from hidden evaluator metadata. This establishes behavior under a controlled evidence-verification task, not real-world source authentication.

Add a held-out source-trust probe with no target securities: reliable and unsupported claims in unrelated synthetic domains. Measure uptake of correct evidence, rejection of unsupported claims, refusal and confidence before/after A training. This is a manipulation check, not proof of a neural arbitration mechanism; do not exclude checkpoints based on its score.

## Analysis and resource decisions (S1, S2, S13)

Three training seeds are for the pilot only. Before confirmation, use pilot variance to select a fixed seed count for a prespecified precision target (95% interval half-width <=0.10 on the primary probability difference); if infeasible, revise scope before confirmation and report the achievable precision. No optional stopping on favorable effects.

Analyze paired effects at 250, treating seed/checkpoint and scenario family as dependence levels and targets as fixed benchmark strata. For the secondary trajectory, summarize each complete paired run with a trapezoidal area under the lift curve over 50–1000 items, normalized by that interval. Report the checkpoint curve descriptively and use a hierarchical bootstrap resampling seed groups and scenario families while retaining paired arms, all checkpoints and shared parents together. With three seeds, intervals are exploratory. Use Holm correction over the declared primary regime/outcome contrasts; specify the Paper 2 primary contrast family before confirmation.

Default to target-specific matched clean trajectories. Reuse is allowed only if the manifest establishes identical clean parent, optimizer initialization, replacement content, token lengths/loss masks, ordering and schedule for all affected contrasts. Seed equality alone is insufficient. Shared controls and parents must retain their dependence in resampling.

Per base model at three seeds, the conservative Paper 1 budget is 24 poison + 24 clean trajectories = 48 runs, 960 exposure adapters and 192,000 generations for 200 queries at every checkpoint. If exact clean reuse is proven, this becomes 30 runs, 600 adapters and 120,000 generations. Add 24 fixed-budget poison runs (4,800 generations) using the full trajectory token/update budget and distributing 250 poison items evenly through it; reuse each valid full-length clean endpoint as its reference. This tests dilution/training-history sensitivity, not order alone. Sequential extension adds 48 endpoint evaluations (9,600 generations). Context, Paper 2, familiarization, warm-up, calibration, capability checks, transfer and control variants must be separately enumerated in the run registry; 195,200 is a previous conditional subtotal, not a complete project budget. Scale all counts with the chosen final seeds and models.

If runtime is prohibitive, before confirmation freeze a family-stratified reduced evaluation schedule and its estimand, or reduce optional extensions. Never drop checkpoints based on observed attack success.
